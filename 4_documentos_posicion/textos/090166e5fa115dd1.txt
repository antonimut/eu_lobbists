 
 
 
 
 
 
 
 
Airlines for America Response to the Advance Air Passenger Information (API) – Revised 
Rules Initiative  
April 3, 2023 
 
Airlines for America (A4A) appreciates the opportunity to submit these comments on behalf of 
its members with service to the European Union (EU)1 in response to the proposed regulations 
amending Regulation (EU) 2019/817 and Regulation (EU) 2018/1726 and repealing Council 
Directive 2004/82/EC and amending Regulation (EU) 2019/818. We strongly support the 
adoption of an advance passenger information (API) program. We applaud the EU’s plans to 
develop a “single window” for airlines to submit API data, as well as plans to standardize the 
data set and timing for API data submissions across all EU Member States. Such a proposal 
limits both operational and administrative burdens on airlines while enhancing passenger 
facilitation.  
 
A4A supports the International Air Transport Association’s (IATA) comments dated March 2023, 
and we offer the following supplemental comments:  
 
I. Methods of Data Collection and Data Quality 
 
A4A members have strong concerns about the proposed requirement to mandate the method 
by which airlines should collect API data – i.e., through automated means only. While 
automation is the airline industry’s preferred means of collecting API data, it does not always 
guarantee that the data will be accurate for each collection/transmission. Airlines should be 
given the flexibility to collect the data in the manner that works best for their individual 
operational needs, their information technology (IT) capabilities, different airport infrastructure, 
travel documents that do not contain a Machine Readable Zone (MRZ) and how airlines 
communicate with their partner airlines. This may include collecting data manually. 
 
In addition, A4A recommends that the regulations incorporate a data quality element for travel 
document validation similar to the U.S. Customs and Border Protection’s (CBP) Document 
Validation Program (DOC VAL) that compares API data to document information that CBP 
already has on file. Through DOC VAL, CBP verifies the API data and uses existing interactive 
communications to advise airlines if the data is on file and if the document is valid. This adds 
additional security and streamlines the check-in process.

proposed API regulations, (ii) the Entry/Exit System (EES) and (iii) the European Travel 
Information and Authorization System (ETIAS) regulations, we request that the responsible

A4A is pleased to see clear budgetary needs outlined in this proposal, particularly for eu-LISA. 
A4A implores the EU to provide the necessary personnel and resources to eu-LISA to ensure 
that sufficient staffing is dedicated to the frequent and real-time technical exchanges with 
airlines that are necessary for implementation of these proposed regulations. A4A members 
already face communication challenges with respect to EES implementation and have raised 
these concerns to the European Commission. Adequate resourcing and expertise in working 
with the airline industry will be crucial to a smooth and timely implementation of the proposals. 
 
III. Data Correction/Completion/Update/Deletion 
 
A4A members would like to better understand the differences between and why differences 
exist in the two proposed regulations with regard to how airlines are expected to correct, 
complete or update/delete API data and the rules for API deletion by airlines after submission 
(48 hours vs. after submission). These differences cause confusion for airlines, and further 
clarity is necessary to determine any system/operational impacts.   
 
IV. Penalties and Data Quality 
 
The existing EU API Directive regime for penalties has led to a disparate approach across EU 
Member States with respect to expectations of data quality (i.e. issuing “standard” fines to 
carriers regardless of the fine trigger such as non-submission, late submission, spelling errors). 
In addition, some Member States have set up additional fine regimes which leads to more 
confusion. A4A requests that the EU establish a standard, agreed-upon framework that is 
incorporated in the regulations for assessing API quality, applicable across all EU Member 
States. Such a framework will standardize expectations and allow airlines to focus on 
enhancements for common data quality concerns. Moreover, airlines should have the 
prerogative to decide how best to address the identified quality issues.
